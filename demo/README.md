# 示例库说明

> 文档版本：v1.0（2026-09-09）· 本文归属《示例库说明》文档类型
> 本目录是随仓库提交的**`.mms`示例库**：用8个示例文件覆盖`.mms`语法v1的全部能力，供功能验收、语法演示与回归测试取材。日常联调请用`../test-vault-local/`（`local`后缀＝本地专用，不入库）。

> 速记：frontmatter四个键`mms_name`／`mms_tags`／`mms_layout`／`mms_desc`；`#`标题定层级（无H6上限）；`--`挂子节点；普通行是正文`content`；`** `是注释`annotation`；`<=>`建跨边；`![[]]`嵌入。写错不会崩——跳级补空节点、缺根自动降级、非法`mms_layout`回退LR，全部在左栏调试信息区给告警。

## 怎么用这些用例

1. **功能验收**：把`demo/`整体复制进vault，逐个打开示例，对照下方「可复制示例」的命中结果核对行为；
2. **语法参考**：不确定某种写法时，先在本目录找同款示例照抄，完整规则查[docs/mms-语言规范.md](../docs/mms-语言规范.md)；
3. **回归取材**：`src/core/parser/demo.test.ts`直接读取本目录文件，增删示例必须同步更新该套件与本文的命中说明；
4. **新语法落地**：新增语法先在`docs/mms-语言规范.md`定规则，再在本目录补一个示例文件，最后补测试用例。

## 可复制示例（按主题分节）

**基础节点与正文**

```mms
# 根节点
## 子节点A
正文属于紧邻的标题节点
-- 孙子节点
```

命中：3个节点；`子节点A`的`content`为「正文属于紧邻的标题节点」；`孙子节点`的父节点是`子节点A`。

**注释与正文分流**

```mms
# 渠道策略
以信息流为主
** 啥信息为主啊，怎么辅以啊
```

命中：`content`为「以信息流为主」，`annotation`为「啥信息为主啊，怎么辅以啊」；注释只在右栏节点注释卡显示，画布不渲染。
变体：把`** `写成`**文字`（星号后无空格）则该行回落为`content`。

**跨父同名保持独立**

```mms
# 用户增长脑图
## 渠道策略
-- 社交裂变
## 拉新策略
-- 社交裂变
```

命中：节点id`用户增长脑图>渠道策略>社交裂变`与`用户增长脑图>拉新策略>社交裂变`同时存在，是两个独立节点。

**同父同名合并**

```mms
## 没有根节点的一级节点
-- 子节点 A
-- 子节点 A
```

命中：合并为一个节点，调试信息区出现一条`duplicate-merge`。

**跨文件引用**

```mms
## 服务层
-- 用户服务
<=> 用户增长脑图.mms::社交裂变	跨文件引用示例
```

命中：单文件解析阶段该引用`resolved`为`false`且`targetFilePath`为`用户增长脑图.mms`；全库扫描完成后`resolved`变为`true`并画虚线。
变体：去掉`用户增长脑图.mms::`前缀即退化为同文件引用。

**多目标跨边与备注**

```mms
<=> 首单转化, 复购	联动转化链路
```

命中：拆成两条crossRef，两条`label`同为「联动转化链路」且都`resolved`。备注前必须用Tab或两个以上空格，单个空格会被并入节点名。

**嵌入四类分流**

```mms
## 数据看板
![[dashboard.png]]
![[详细分析.mms]]
![[财报.pdf]]
https://example.com
```

命中：`embeds`的`kind`依次为`image`、`mms`、`file`、`url`；裸URL行同样计为`url`。

**跳级补空节点**

```mms
### API 网关
##### 限流熔断
```

命中：中间缺失的一层自动补出空节点（`isAutoFix`为`true`），调试信息区出现一条`level-skip`。

**缺根降级与非法layout**

```mms
---
mms_layout: XX
---
## 没有根节点的一级节点
```

命中：`rootId`为「没有根节点的一级节点」，`layout`回退为`LR`，调试信息区出现一条`no-root`。

**空文件**

命中：节点数为0、`rootId`为`null`，画布显示空态提示而非报错。

## 操作

1. 构建：在仓库根目录执行`node esbuild.config.mjs once`，把产物同步到测试vault插件目录；
2. 启用：Obsidian→设置→第三方插件→关闭安全模式→启用Mind Map Show；
3. 取材：把`demo/`整体复制进vault，或直接把`demo/`当vault打开；
4. 挂载：点ribbon图标`git-fork`，或执行命令`MMS：打开文件面板`；
5. 浏览：在文件树点开示例，用工具栏切换探索视图与全景视图；
6. 校验：点画布节点看右栏详情，再对照左栏调试信息区核对告警类型与行号。

## 开发

```bash
cd ..                       # 从 demo/ 回到仓库根目录
npx vitest run              # 跑示例库回归：demo.test.ts 直接读取本目录素材
node esbuild.config.mjs once # 重新构建并同步插件产物
```
