# 示例库说明

> 文档版本：v1.4（2026-09-09）· 本文归属《示例库说明》文档类型
> 本目录是随仓库提交的**`.mms`示例库**：17个示例文件按**功能用例**分7个目录，供功能验收、语法演示与回归测试取材。
> 找用例按目录名直接定位：看反链去`跨边与反链/`，看四种流向去`布局方向/`，看连线画法去`连线样式/`，看兜底行为去`边界与异常/`，看节点指令去`指令扩展/`。
> 日常联调请用`../test-vault-local/`（`local`后缀＝本地专用，不入库）。

> 速记：frontmatter五个键`mms_name`／`mms_tags`／`mms_layout`／`mms_line`／`mms_desc`；`#`标题定层级（无H6上限）；`--`挂子节点；普通行是正文`content`；`** `是注释`annotation`；`<=>`建跨边；`::`定位节点（不建边）；`![[]]`嵌入；`!-- key > value <-- 目标`是节点级指令。写错不会崩——跳级补空节点、缺根自动降级、非法`mms_layout`回退LR、非法`mms_line`回退line，全部在左栏调试信息区给告警。

## 怎么用这些用例

1. **功能验收**：把`demo/`整体复制进vault，逐个打开示例，对照下方「可复制示例」的命中结果核对行为；
2. **语法参考**：不确定某种写法时，先在本目录找同款示例照抄，完整规则查[docs/mms-语言规范.md](../docs/mms-语言规范.md)；
3. **回归取材**：`src/core/parser/demo.test.ts`直接读取本目录文件，增删示例必须同步更新该套件与本文的命中说明；
4. **新语法落地**：新增语法先在`docs/mms-语言规范.md`定规则，再在本目录补一个示例文件，最后补测试用例。

## 可复制示例（按主题分节）

**基础节点与正文**

```mms
# 根节点
## 子节点A
正文属于紧邻的标题节点
-- 孙子节点
```

命中：3个节点；`子节点A`的`content`为「正文属于紧邻的标题节点」；`孙子节点`的父节点是`子节点A`。

**注释与正文分流**

```mms
# 渠道策略
以信息流为主
** 啥信息为主啊，怎么辅以啊
```

命中：`content`为「以信息流为主」，`annotation`为「啥信息为主啊，怎么辅以啊」；注释只在右栏节点注释卡显示，画布不渲染。
变体：把`** `写成`**文字`（星号后无空格）则该行回落为`content`。

**跨父同名保持独立**

```mms
# 用户增长脑图
## 渠道策略
-- 社交裂变
## 拉新策略
-- 社交裂变
```

命中：节点id`用户增长脑图>渠道策略>社交裂变`与`用户增长脑图>拉新策略>社交裂变`同时存在，是两个独立节点。

**同父同名合并**

```mms
## 没有根节点的一级节点
-- 子节点 A
-- 子节点 A
```

命中：合并为一个节点，调试信息区出现一条`duplicate-merge`。

**跨文件引用**

```mms
## 出链
-- 引用复购
<=> 综合演示/用户增长脑图.mms 复购	出链：本文件指向外部节点
```

命中：单文件解析阶段该引用`resolved`为`false`且`targetFilePath`为`综合演示/用户增长脑图.mms`；全库扫描完成后`resolved`变为`true`并登记到目标节点入链。完整文件见`跨边与反链/跨文件引用.mms`。
变体：去掉`综合演示/用户增长脑图.mms `前缀即退化为同文件引用（`<=> 复购`）；带目录的写法按后缀匹配，写`用户增长脑图.mms 复购`也能命中；目标文件里有多个同名节点时指向第一个并记`info`告警（见`综合演示/技术架构.mms`引用「社交裂变」）。

**节点引用 `::`**

```mms
## 引用链
-- 引用订单服务
:: 综合演示/技术架构.mms::订单服务
```

命中：`::` 只做点对点定位（`resolved`回填为`true`），不建边、不画虚线、不产生入链/出链；右栏「引用链」卡以`::`前缀显示目标节点名并可跳转（`<=>`条目以`→`前缀混排在同一张卡）。同文件写`:: 节点文本`即可。

**多目标跨边与备注**

```mms
<=> 首单转化, 复购	联动转化链路
```

命中：拆成两条crossRef，两条`label`同为「联动转化链路」且都`resolved`。备注前必须用Tab或两个以上空格，单个空格会被并入节点名。

**嵌入四类分流**

```mms
## 数据看板
![[dashboard.png]]
![[详细分析.mms]]
![[财报.pdf]]
https://example.com
```

命中：`embeds`的`kind`依次为`image`、`mms`、`file`、`url`；裸URL行同样计为`url`。

**节点级指令 `!--`**

```mms
!-- background > #FDF6E3 <**孤儿指令：首个节点声明之前，挂文档级（渲染时作全文档兜底）

# 首页
** 对照组：自身无指令，米白底（#FDF6E3）来自文档级兜底

## 文字色分支
!-- color > #E74C3C
** color＝文字色（#E74C3C＝正红）：探索与全景两视图一致，均染文字不染底色

## 背景色分支
!-- background > #F1C40F
** background＝背景色（#F1C40F＝明黄）：DOM落background-color，SVG映射矩形fill

## 连线分支
!-- line-color > #3498DB
!-- line-width > 3
** line-color＋line-width：连到本节点的线变湖蓝（#3498DB＝湖蓝）、加粗到3（默认2）

## 折叠分支
!-- collapsed
** collapsed＝初始折叠：徽标显示+1；点击展开／收起直接写回文档指令行，持久化即文档
-- 折叠期间不可见
** 折叠期间不参与布局，展开后恢复

## 调试与锁定
!-- debug
!-- locked
** debug＝左上角灰底小签显示「节点id·源码行号」；locked＝禁点击选中＋右栏置灰

!-- color > #E67E22 <-- ## 前向引用分支
## 前向引用分支
** <--目标绑定：指令写在节点上方，指名绑给下方未声明的节点；文字色＝橙（#E67E22）
```

命中：紧随声明行的指令默认绑定到上方最近的节点（如`文字色分支`得`{ color: '#E74C3C' }`）；`<--`目标绑定支持前向引用；样式类key（color／background／line-color／line-width及text-color／border-radius／opacity）沿祖先链就近继承，行为类key（collapsed／debug／locked）仅自身生效不传播；行尾注释`<**`到行尾整段剥离（含其后的`<--`）。
变体：`!-- line color > red`的key归一化为`line-color`；`<-- ## 目标`按「#个数=声明层级 + 文本精确匹配 + 最近距离」寻址；同节点同key保留先写者并记`directive-conflict`；目标层级不匹配记`directive-target-missing`；仅支持规范§10.7清单内10个key，清单外key记`directive-unknown-key`且不存储。全部10个key的逐节点效果与颜色中文名备注见`指令扩展/指令进阶.mms`。

## FAQ

### Q：引用链/入链/出链显示为空，是解析出问题了吗？

不是，三张卡的空态含义不同：
- **引用链为空**＝选中节点没有写任何`<=>`或`::`；
- **入链为空**＝没有任何节点的`<=>`指向选中节点（含本文件）；
- **出链为空**＝当前文件没有指向**外部**文件的`<=>`（同文件引用只进「引用链」卡，不进「出链」）。

这些都是正常状态，不会产生任何警告。只有当 `<=>` 跨文件引用的目标文件或目标节点不存在时，才会在调试信息区出现 `missing-target` 警告，同时对应的引用链条目显示为灰色断链状态。

### Q：跨文件 `<=>` 指向的节点明明存在，入链却落在另一个同名节点上？

`<=>` 按节点文本匹配，目标文件有多个同名节点时**指向第一个**（文档顺序），并记一条`info`告警说明落点（如`综合演示/技术架构.mms`引用「社交裂变」落在渠道策略分支下）。要精确落点，引用唯一命名的节点。

## 操作

1. 构建：在仓库根目录执行`node esbuild.config.mjs once`，把产物同步到测试vault插件目录；

5. 浏览：在文件树点开示例，用工具栏切换探索视图与全景视图；
6. 校验：点画布节点看右栏详情，再对照左栏调试信息区核对告警类型与行号。
