# .mms 语言规范

> Mind Map Show (MMS) 的源文件格式。文档版本：v1.4（2026-09-10）· 语法版本：`.mms` v1.4

`.mms` 是文本文件，扩展名 `.mms`，MIME `text/plain`。语法借鉴 Markdown + 少量自定义符号。所有功能基于这套规范实现，插件只是规范的渲染器。

---

## 1. 文件结构

```
---
mms_name: 显示名
mms_tags: [标签1, 标签2]
mms_layout: TB | BT | LR | RL
mms_line: line | curve | elbow
mms_desc: 文件级备注（多行）
---

# 正文开始
... 节点与正文 ...
```

| 部分 | 是否必须 | 作用 |
|---|---|---|
| Frontmatter | 否 | 5 个固定键，否则忽略 |
| 正文 | 否 | 节点用 `#` 标题 / `--` 子节点；正文 / 注释 / 嵌入 / 跨边 |

文件可空：空文件 → 节点树空 + `no-root` 警告。

---

## 2. Frontmatter

YAML 风格，必须在文件**开头**且三连横线包裹。

### 2.1 字段清单

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `mms_name` | string | 文件名去后缀 | 文件浏览器与右栏显示名 |
| `mms_tags` | string[] | [] | 用于左栏标签云过滤 |
| `mms_layout` | 'TB' \| 'BT' \| 'LR' \| 'RL' | 'LR' | 布局方向，见 §2.3 |
| `mms_line` | 'line' \| 'curve' \| 'elbow' | 'line' | 连线样式，见 §2.4 |
| `mms_desc` | string | '' | 文件级备注，右栏"备注"行展示 |

非法值：
- 缺 `: ` → 字段忽略
- `mms_layout: XX` → 回退 LR，记 `warning`
- `mms_line: ZZ` → 回退 `line`
- `mms_tags` 元素含逗号 → 拆分为多标签
- `mms_tags` 类型错（不是数组 / 字符串） → 整字段忽略

`mms_tags` 支持三种写法（等价）：同行逗号 `mms_tags: a, b`、内联数组 `mms_tags: [a, b]`、YAML 块列表（`mms_tags:` 后逐行缩进 `- a`）。块列表是 Obsidian「笔记属性」面板对列表型属性的固定写入格式，必须兼容；块列表项的首尾引号与行尾逗号会被剥离，列表在下一个键或 `---` 边界处结束。

`mms_layout` 与 `mms_line` 的取值大小写不敏感（`bt` / `CURVE` 均合法）。

### 2.3 布局方向定义

方向一律以**父节点 → 子节点**的流动方向为准，与观察顺序无关：

| 关键字 | 布局类型 | 流向描述 | 子节点展开轴 | 根位置 |
|---|---|---|---|---|
| `TB` | 垂直布局 | 父节点在上，子节点向下展开（Top → Bottom） | 水平（X 轴） | 顶部 |
| `BT` | 垂直布局 | 父节点在下，子节点向上展开（Bottom → Top） | 水平（X 轴） | 底部 |
| `LR` | 水平布局 | 父节点在左，子节点向右展开（Left → Right） | 垂直（Y 轴） | 左侧 |
| `RL` | 水平布局 | 父节点在右，子节点向左展开（Right → Left） | 垂直（Y 轴） | 右侧 |

- 「布局类型」决定**主轴**：垂直布局沿 Y 轴推进层级，水平布局沿 X 轴推进层级。
- 「子节点展开轴」是**交叉轴**：同一父节点下的兄弟沿该轴依次排开，与主轴垂直。
- `BT`／`RL` 是 `TB`／`LR` 的主轴翻转，节点尺寸与交叉轴坐标不变，只有主轴坐标镜像。
- 连线的锚点随之变化：`TB` 父下中→子上中、`BT` 父上中→子下中、`LR` 父右中→子左中、`RL` 父左中→子右中。

### 2.4 连线样式 `mms_line`

| 值 | 画法 | 说明 |
|---|---|---|
| `line` | 直线 | 起终点直接线性插值 `P(t) = P₀ + t(P₃ - P₀)`，缺省值 |
| `curve` | 三次贝塞尔曲线 | 带几何约束的控制点推导，见下 |
| `elbow` | 直角折线 | 先沿流向轴走到中线，再沿展开轴平移，最后落点 |

`curve` 的几何约束（实现见 `src/render/shared/edges.ts:buildEdgePath`）：

- **安全推力** `h = max(5, min(H₀, |Δspread| × 0.45))`，`H₀` 为当前视图的层级间距；
- **正对直连补偿**：展开轴位移为 0 时强制 `h ≥ 25`，保证直连也看得出弧度；
- **极限陡坡增压**：流向轴位移超过展开轴位移的 3 倍时，`h ≥ |Δflow| × 0.18`；
- **防错**：左子节点恒向左鼓、右子节点恒向右鼓（垂直布局），控制点永不交错，杜绝回环与尖刺。

`mms_line` 只影响连线形状，不影响布局坐标；跨文件引用虚线同样遵循该样式。

### 2.2 行号

parser 在 frontmatter 处理阶段记录 `bodyStartLine`，节点 lineNo = frontmatter 行数 + 当前正文行号。这样源码跳转定位到行号永远准确。

## 3. 节点

### 3.1 标题节点

以 `#` 开头，1 到 N 个（不限 H6）。N 决定 depth。

```
# 根        depth 0
## 子1      depth 1
### 子子1    depth 2
...       ...
########## 深度10  depth 9（无上限）
```

**跳级**：从 `#` depth 1 直接跳到 `#` depth 3 → 自动补 1 个空节点（`type: auto` + `isAutoFix: true` + 占位 text ''），记 `level-skip` info。

**缺根**：首个标题不是 `#`（如首个就是 `##`） → 把首个标题降级为根，记 `no-root` warning。

### 3.2 子节点 `--`

紧跟最近标题，作为该标题的子级：

```
## 父节点
-- 子 1       depth 父 + 1
-- 子 2
-- 子 3
```

多个 `--` 是兄弟，与父标题同级。

### 3.3 节点 id

```
id = parentId === null ? text : parentId + '>' + normalizedText
```

`normalizedText`：去除前后空白、合并连续空白、去掉零宽字符。

### 3.4 同名合并

**仅同父下合并**（用户决策，与原"全局同名合并"的方案设计不一致）：

```
# R
## A
-- x
-- x         <- 同父同名合并，记 duplicate-merge info
## B
-- x         <- 跨父同名，独立节点
```

合并后：`node.parentIds = ['R>A', 'R>A']`（同父多次累积）、`childIds` 唯一、`isAutoFix: false`。文本节点属性 (text / depth / lineNo) 取首次出现的。

---

## 4. 正文 content

紧跟标题（`#` 或 `--`）的非空行，属于该节点的 `content`。

支持多行，直到遇到以下任一前缀：

- 下一个 `#` 标题
- 下一个 `--`
- 一条 `<=>`
- 一条 `![[...]]`
- `**`（注释行；见 §5）
- 一条 `!--` 指令（见 §10）

正文行内的行尾注释 `<**` 到行尾整段剥离，不进入 `content`（规则见 §10.2）。

```
# 标题
正文行 1
正文行 2
## 下一个
```

正文只用于右栏「节点详情」卡展示，画布上**默认不渲染**（避免视觉拥挤）。

---

## 5. 注释 annotation

以 `**` 开头的行属于 `node.annotation`。

| 语法 | 字段 |
|---|---|
| `** 文字`（中间至少一空格） | `node.annotation` |
| `**文本`（紧贴，无空格） | `node.content` |

支持多行，遇到下一个 `#` / `--` / `<=>` / `![[` 终止。

```
# 渠道策略
以信息流为主。
** 啥信息为主啊，怎么辅以啊   <- annotation
-- 信息流投放
预算占比 60%。
** 投放时段需避开晚高峰      <- annotation
```

annotation 在右栏「节点注释」卡显示（斜体小字 + 蓝条 + 灰底）。**画布默认不展示**——避免视觉拥挤。如需画布显示，可未来加 tooltip 触发。

---

## 6. 跨边引用 `<=>`

`<=>` 在某节点下写一条跨边，指向（可同文件 / 跨文件）其他节点。

```
<=> 目标1, 目标2    备注文字
```

- `目标` 单个 = 直接写节点文本（按文本匹配）
- `目标` 跨文件 = `文件名.mms 节点文本`（**空格分隔**，文件名以 `.mms` 结尾）
- 多个目标 = `,` 分隔
- `目标, 目标2` 后接 `备注`：分隔用 **Tab 或两个以上空格**（普通空格会被识别为名称的一部分）
- 备注缺省 = 空

> `<=>` 的跨文件目标用空格分隔（`<=> 文件.mms 节点`），**不是** `::`。`::` 保留给下文的节点引用（§6.4）。

### 6.1 解析时机

第一遍扫描收集 pending refs，第二遍在全部文档解析完后回填 `resolved`，因此支持**前向引用**。

### 6.2 状态

| 状态 | 含义 |
|---|---|
| `resolved=true` | 找到目标节点，画虚线 |
| `resolved=false` | 找不到，记 `missing-target` warning，虚线不绘 |

### 6.3 多目标

`<=> B, C    备注` 拆为两条 crossRef 到 B、C；两条共享 label。

### 6.4 节点引用 `::`

`::` 在某节点下写一条节点引用，只做**点对点定位**：不建边、不画虚线、不产生入链/出链。

```
:: 节点文本               同文件
:: 文件名.mms::节点文本    跨文件
```

- 同文件 = `:: 节点文本`（按文本匹配）
- 跨文件 = `:: 文件名.mms::节点文本`
- 解析：遇 `::` 拆分为 `[targetFile, targetNodeText]`；无 `::` 视为同文件节点
- 用途：右栏「引用链」卡以 `::` 前缀展示目标节点名，可点击跳转定位
- 定位失败**不产生警告**，仅在「引用链」卡灰显断链状态

与 `<=>` 的分工：`::` = 「去哪儿」（定位），`<=>` = 「连谁」（建边），两者独立、互不嵌套。

### 6.5 右栏展示

选中节点后，右栏三张卡与引用数据一一对应：

| 卡片 | 粒度 | 内容 |
|---|---|---|
| 引用链 | 节点 | 该节点的全部对外引用：`<=>` 以 `→ 目标（备注）` 列出，`::` 以 `:: 目标` 列出；断链灰显 |
| 入链 | 节点 | `<=>` 指向该节点的全部来源；同文件来源显示为「本文件 → 第 N 行」 |
| 出链（文件级） | 文件 | 当前文件指向**外部**文件的 `<=>` 聚合；同文件引用只进「引用链」 |

## 7. 嵌入 `![[]]`

`![[target]]` 当行出现任意位置都计入 `node.embeds`。

按扩展名或协议分流：

| target | kind | 说明 |
|---|---|---|
| `*.png/jpg/jpeg/gif/svg/webp/bmp/avif` | `image` | 图片 |
| `*.mms` | `mms` | 脑图链接 |
| 其他 `*.ext` | `file` | 通用文件 |
| `https?://...` | `url` | URL |

同一行可多个 `![[]]`，顺序按出现。

裸 URL 行（以 `http://` 或 `https://` 开头）也算 url 嵌入。

## 8. 警告体系

`IWarning.type`：

| type | severity | 触发 |
|---|---|---|
| `parse-error` | warning | 解析时无法读取某行 |
| `no-root` | warning | 文件缺 # 根 |
| `level-skip` | info | 跳级（自动补空节点）|
| `missing-parent` | warning | `--` 之前没标题（已建自动根）|
| `missing-target` | warning/info | `<=>` 目标不存在 |
| `duplicate-merge` | info | 同名节点已合并 |
| `bad-frontmatter` | warning | YAML 非法 |
| `directive-target-missing` | warning | `!--` 指令的 `<--` 目标寻址失败（层级不匹配或文本不存在），指令不绑定（§10.5） |
| `directive-conflict` | warning | 同一节点同一 key 的指令重复，保留先写者（§10.6） |

写调试信息卡可见，按 severity 排序。

## 10. 节点级指令 `!--`

> v1.3 新增语法，无存量兼容负担。完整示例见 `demo/指令扩展/`。

### 10.0 符号体系

指令占用 `!--` / `<--` / `<**` 三个符号。

**禁止：**

- 不得占用 `<!--`（预留给未来块注释）
- 不得让 `<=>` / `::` / `![[` / `**` 的既有识别逻辑受指令语法影响

### 10.1 行格式

```
!-- [key] > [value] <-- [目标] <** 行尾注释
```

**边界裁决：**

- 分流优先级：`!--` 低于 `#…` / `--` / `<=>` / `::` / `![[` / `**`，仅在上述前缀全部不匹配且行首 trim 后匹配 `!--` 时进入指令解析
- 指令行内的 `![[` 属于 value / 目标文本，**不入 embeds**
- `<--` 右侧为空 → 视同无目标（默认绑定）
- 无有效 key（`!--` 或 `!-- > 值`）→ 静默忽略，不产生警告

### 10.2 解析顺序

1. **剥注释**：行内首个 `<**` 到行尾丢弃（其后即使有 `<--` 也一并丢弃）
2. **切目标**：以第一个 `<--` 为界切左右（右侧为空 → 见 §10.1 边界裁决）
3. **切 kv**：左半段按第一个 `>` 切分 key / value；无 `>` 时 value = `''`；value 中的其余 `>` 原样保留
4. **解析目标**：目标段按 §10.5 规则解析深度前缀与节点文本

行尾注释 `<**` 同样作用于标题行、`--` 行与正文行：`## 你好 <**注释` 的标题文本为「你好」。

### 10.3 key 规范

- **归一化**：去除首尾空格 → 连续空格归一化为单个 `-` → 转小写（`line color` → `line-color`）
- **未知 key**：记 `directive-unknown-key` warning（含行号与 key 原文），指令不存储。仅支持 §10.7 清单内的 key，不开放自定义扩展
- **类别语义**（标准 key 清单以 §10.7 为唯一权威来源）：
  - 行为类 value 为布尔语义：trim + 不区分大小写，空 value 归 `'true'`，其余非 `'false'` 值一律按 `'true'` 处理
  - 样式类 value 仅 trim，区分大小写（颜色值等原样保留）；`!-- color` 与 `!-- color >` 行为一致，均存 `''`

### 10.4 绑定与继承

- **默认绑定**：无 `<--` 时，指令存入其上方最近的一个节点声明行（`#` 系列 / `--`）的 extensions。指令块可穿插 `**` 注释行、空行、`<=>`、`![[`，均不打断绑定；仅新的节点声明行结束指令块
- **孤儿指令**：文件首个节点声明之前的指令 → 挂到文档级 `document.extensions`
- **继承**：发生在渲染阶段——渲染子节点时沿祖先链查找 extensions，就近覆盖；不复制指令（实现见 `render/shared/extensions.ts:resolveExtensions`）。行为类不参与继承
- **冗余写法**：目标节点紧下方写 `<--` 指向该节点自身，与默认绑定等价（合法，不报错；linter 可提示）

### 10.5 目标寻址（`<--`）

目标格式：`[#+] 节点文本`

- 连续 `#` 的个数 = 目标节点声明层级（精确匹配）；`#` 后必须有空格，其余为节点文本
- `--` 子节点按结构层级（depth + 1）参与匹配，与同层的 `#` 标题可被同一前缀寻址
- 无 `#` 前缀 → 层级不限，仅按文本匹配

**匹配规则：**

- 全文档扫描所有「层级精确相等 + 节点文本 trim 后精确匹配（区分大小写）」的节点
- 取与指令行行号距离最小者（不区分上下方向）
- 距离相同 → 文档序靠前（上方）者胜出

**其他：**

- 支持前向引用（目标可声明在指令下方）→ 解析器必须两遍扫描：先建节点树，再统一回填指令
- 无匹配 → `directive-target-missing` warning（含行号与目标文本），指令不绑定，解析不报错、不影响退出码
- 不可寻址：节点文本以 `#` 开头、含 `>` / `<--` / `<**` 时无法被寻址（文档级限制）
- 不支持：`[n]` 索引、路径语法、相对寻址、模糊匹配

示例：

```
# 你好
!-- color > #ffff <-- ## 不好
## 不好          ← 距离 1，命中此处
# 其他
## 不好          ← 距离更远，不命中
```

### 10.6 冲突处理（同一节点上的同一 key）

- 时机定义：「先后」以源文件行号顺序为准；冲突检测在回填阶段执行
- 同一容器（同一节点 / 文档级）上的同一 key（归一化后）→ 保留先写者，后到者记 `directive-conflict` warning
- 不同节点上的同名 key、同一节点上的不同 key 均不冲突

### 10.7 标准 key 清单（唯一权威来源）

总原则：标准 key 只声明语义，不声明 CSS 属性。渲染器负责语义到当前画法（DOM 探索视图 / SVG 全景视图）的实现；`KNOWN_DIRECTIVE_KEYS`（白名单常量，`core/parser/directive.ts`）与 `KEY_RENDERERS`（渲染映射表，`render/shared/extensions.ts`）同置一处、同 PR 维护。

渲染兼容性映射：

| key | 类别 | DOM（探索视图） | SVG（全景视图） |
|---|---|---|---|
| `color` | 样式类 | `color` | `fill`（文本元素） |
| `text-color` | 样式类 | `color` | `fill`（文本元素） |
| `line-color` | 样式类 | 连线 `stroke` | `stroke` |
| `line-width` | 样式类 | 连线 `stroke-width` | `stroke-width` |
| `border-radius` | 样式类 | `border-radius` | `rx` |
| `background` | 样式类 | `background-color` | `fill`（映射） |
| `opacity` | 样式类 | `opacity` | `opacity` |
| `collapsed` | 行为类 | 折叠状态机（交互层） | 同左 |
| `debug` | 行为类 | 调试叠加层（交互层） | 同左 |
| `locked` | 行为类 | 禁拖拽 + 编辑入口置灰（交互层） | 同左 |

补充裁决：

- 行为类三个 key 接交互层，与画法无关，在映射表中无样式落点；不参与继承（§10.4）
- 两种画法的连线均为 SVG path：`line-color` / `line-width` 只作用于连线（树边取子节点端的有效 extensions），不作用于节点元素
- 同落点冲突按上表声明顺序应用、后者覆盖前者：`text-color` 与 `color` 在两种画法中同落文字色，`text-color` 声明在后胜出；`background` 独占 SVG 矩形填充，不受 `color` 影响（两画法下 `color` 均为文字色语义，探索与全景视觉一致）
- 样式 value 经归一化器校验（合法颜色 / 数字，`opacity` 收敛到 [0,1]），非法值不应用、静默忽略（防 CSS 注入）
- `transform` / `shadow` / `transition` / `line-dash` / `font` 等因 DOM/SVG 双画法落地成本或语义不对等问题未纳入清单，写了即按未知 key 告警（§10.3）

带空格写法（如 `line color`）经 §10.3 归一化后与标准名等价。

### 10.8 数据模型

- `IMmsNode` 增加可选字段 `extensions: Record<string, string>`
- `IParsedDoc` 增加可选字段 `extensions: Record<string, string>`
- `IParsedDoc` 增加可选字段 `directiveBindings: ReadonlyArray<{ key, lineNo, nodeId | null }>`：成功绑定指令的行索引（按文档序），供 UI 写回文档时定位指令行（如折叠徽标删除 / 改写 `collapsed` 行）
- 警告体系新增：`directive-target-missing`、`directive-conflict`、`directive-unknown-key`（均 severity: warning）

### 10.9 简单示例

**示例一：行尾注释剥离 + 最近距离寻址**

```
## 你好 <**行尾注释在标题行生效
!-- color > #ffff <-- ## 你好
## 不好
# 其他
## 不好
```

期望：

- 标题 `## 你好` 获得 `{ color: '#ffff' }`（`<**` 起的内容被剥离，不进入标题文本）
- 两个 `## 不好` 均无 extensions

**示例二：默认绑定 + 多 `>` value + 行为类**

```
# 首页
!-- color > #2C3E50
!-- background > linear-gradient(red > blue) <-- ## 详情页
## 详情页
-- 组件A
-- 组件B
!-- collapsed <-- ## 详情页
```

期望：

- 首页：`{ color: '#2C3E50' }`
- 详情页：`{ background: 'linear-gradient(red > blue)', collapsed: 'true' }`（value 中的 `>` 原样保留；collapsed 仅自身，不传播）
- 组件A / 组件B：`{}`，渲染时沿祖先链继承 color（DOM 落 `color`，SVG 落 `fill`）

### 10.10 实现边界

- 两遍扫描：第一遍建节点树 + 收集指令（白名单拦截在收集时执行），第二遍回填（寻址 + 冲突裁决），复用 `<=>` 的 pending 队列骨架
- 单遍解析的既有逻辑保持不变，`<=>` / `::` / `![[` / `**` 解析不得回归
- 渲染落地：`render/shared/extensions.ts` 提供 `KEY_RENDERERS` 映射与 `createDirectiveRuntime` 运行时，DOM 探索视图与 SVG 全景视图共用；折叠徽标点击直接写回文档 `collapsed` 指令行（插入到声明行之后 / 改写显式 `> false` / 删除绑定行），持久化即文档本身、不进设置文件；写回后经 vault modify 事件防抖重扫重渲染；`collapsed` 是唯一由 UI 写回文档的指令，`debug` / `locked` 仅由用户手写
- SVG 交互性（设计澄清）：SVG 图元（`<g>`／`<rect>`／`<text>`）是一等 DOM 元素、继承自 `EventTarget`，`addEventListener` 直接生效；全景视图「静态全量」仅指渲染内容（一次全量画完、不做增量更新），不预设交互能力上限。已接入交互：节点选中联动（右栏三卡跟随切换）、折叠徽标点击（同一条 `collapsed` 写回管线，重扫后 SVG 重渲染）、`locked` 拦截（禁点击选中，光标 `not-allowed`，`<title>` 提示「已锁定」）。两视图节点事件均按事件委托实现：根（`<svg>` / 画布容器）挂单一 click listener，`event.target.closest('[data-node-id]')` 反查节点（每个节点元素已打 `data-node-id`），折叠徽标经 `.mms-svg-fold` / `.mms-fold-btn` 优先分流（`is-collapsed` class 即点击前状态载体），`locked` 经 `is-locked` class 拦截；一个 listener 管全部节点，重渲染免重绑
- 明确不做（v1 范围外）：多目标逗号列表、`[n]` 索引、路径/相对寻址、路径转义、模糊匹配；`<--` 多次出现（首个生效，其余属目标文本）；清单外 key 的存储与渲染（一律 `directive-unknown-key` 告警）
- 测试覆盖：`<**` 在标题行 / 指令行 / content 行的剥离、`#` 无空格不作为标题、最近距离匹配（含上下双向与同距取上方）、深度不匹配触发 warning、冲突保留先写者、孤儿指令挂文档级、行为类 value 表全分支、key 归一化、未知 key 告警不存储、指令行内 `![[` 不入 embeds、DOM/SVG 样式映射与值校验、折叠剪枝、渲染运行时聚合

### 11.4 `::` 与 `<=>` 的语义分工

| 语法 | 用途 | 目标格式 | 示例 |
|---|---|---|---|
| `::` | **节点引用**（点对点定位） | `文件名.mms::节点文本`（跨文件）或 `节点文本`（同文件） | `用户增长脑图.mms::社交裂变` |
| `<=>` | **跨边引用**（建立有向边） | `<=> 文件名.mms 节点文本 备注` | `<=> 用户增长脑图.mms 社交裂变 跨文件引用示例` |

**`::`（节点引用）** —— 定位节点，不建立关系，不产生入链/出链。
- 同文件：`::节点文本`
- 跨文件：`文件名.mms::节点文本`
- 用途：跳转定位（右栏「引用链」卡以 `::` 前缀列出）
- 解析：遇 `::` 拆分为 `[targetFile, targetNodeText]`；无 `::` 视为同文件节点

**`<=>`（跨边引用）** —— 建立有向边，产生入链/出链登记，画布绘制虚线。
- 同文件：`<=> 节点文本 备注`
- 跨文件：`<=> 文件名.mms 节点文本 备注`
- 用途：建立引用关系；右栏「引用链」以 `→ 目标（备注）` 列出，目标节点「入链」登记来源（同文件来源显示为「本文件」），跨文件条目另计入文件级「出链」

**组合规则：**

| 写法 | 结果 |
|---|---|
| `::节点文本` | 同文件节点引用，不建边 |
| `文件名.mms::节点文本` | 跨文件节点引用，不建边 |
| `<=> 节点文本` | 同文件引用链，画虚线 |
| `<=> 文件名.mms 节点文本` | 跨文件出链/入链，画虚线 |
| `<=> 文件名.mms::节点文本` | **非法** —— 应拆为 `<=> 文件名.mms 节点文本` |

**设计原则：**
- `::` = 「去哪儿」（定位）
- `<=>` = 「连谁」（建边）
- 两者独立，互不嵌套

## 12. 反向不兼容改动
